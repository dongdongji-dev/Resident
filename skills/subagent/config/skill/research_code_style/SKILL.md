# 科研脚本代码风格（research code style）

> 一句话：让代码写成**实验记录**，而不是**软件产品**——线性、命令式、一步一行、看得懂优先。
> 来源：基于 B站 silencedream《AI辅助科研》第八期《让AI写出研究者风格的代码》的思路，
> 补充适用边界、示例对照与工程化切换路径。**本技能目录自包含、平台无关**：
> 原封不动拷贝到任何支持 SKILL.md 的 skills 目录（含其他 agent / 其他项目）即可使用。

## 同目录文件

- `researcher_coding_style.md` —— 完整版（判据表 / 七条规则 / 正反例对照 / 各平台接入方式 / 中英提示词 / 切回工程风格）
- `style_prompt_zh.txt` `style_prompt_en.txt` —— 可直接粘贴进任何聊天窗口或规则文件的提示词

## 先看判据

**这段代码是"读一次就跑一次"，还是"会被反复调用"？**
前者用研究风格；后者（工具 / CLI / 服务 / 库 / 进数据管道的资产）用工程风格——
变量进配置、有校验、有日志、有测试。两套规则管的是不同对象，不冲突。

## 七条规则

1. **线性 + 命令式**：按执行顺序从上往下写（读入 → 清洗 → 变换 → 建模 → 保存），不要先堆类/函数定义。
2. **少封装**：不为"以后可能复用"抽函数；真的重复三次以上再抽。
3. **少循环**：能直接表达就直说，"一眼看清在干什么"比"写法优雅"值钱。
4. **不写防御性代码**：不默认 `try/except`、不重复校验已知输入；报错本身就是信息。
5. **不为格式拆行**：一行能说清就一行，只有过长才换行。
6. **变量名说人话**：用领域词（age / group / score），保留可见的中间结果。
7. **打印关键中间结果**：行数 / 形状 / 前几行 / 分组计数，跑一次就能自证对不对。

## 代价与切换

代价：复用性差、改动要改多处、没有错误处理。
所以一旦脚本开始被**反复运行 / 给别人用 / 接进数据管道**，明确说一句"这段按工程风格重写"；
也可以让文件开头声明模式（如 `# mode: research-script`），人和 AI 都一眼知道该用哪套规矩。

## 使用方式（跨平台）

把本目录拷到目标平台的 skills 目录即可；如果只想快速生效，把 `style_prompt_zh.txt` 的内容
贴到该平台的规则文件里也行：OpenCode / Codex 用 `AGENTS.md`，Claude Code 用 `CLAUDE.md`，
Cursor 用 `.cursorrules`，聊天窗口直接粘贴。

## 维护

本目录是**源**；各平台（含子代理框架的全局技能目录）用的是**拷贝**，不会自动跟着变。
改完本目录后，把整个目录重新拷到那些位置覆盖即可（`cp -r <本目录> <目标 skills 目录>/`）。
子代理侧已实测可扫描 + `load_skill` 正常加载（`<skills>/<name>/SKILL.md` 格式）。
