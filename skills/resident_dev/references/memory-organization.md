# 记忆的推荐组织方式（Resident 通用参考文档）

> 本文给的是**推荐结构**，不是硬模板——各部署可以自己调整，但「哪类东西放哪一层」的分工别混。
> 假定记忆落在工作区的 `memory/`（用 git 管理，可回滚、可迁移）。

---

## 1. 前提：上下文只是工作缓存

- 上下文在压缩后会被折叠/丢弃，**没写进文件的判断等于不存在**。行事口径：**写完才是真的，读到才算数**——把自己当随时会遗忘的人。
- 记忆是**写给「压缩后的自己」**看的东西：入口、索引、规则、状态。写作时假定读者对这次会话一无所知。
- 凡「我做过 / 说过 / 交付过 / 某人发过某物」的断言，一律回查**可验证来源**（消息库、产物文件、git 历史）再讲；摘要与上下文只是线索。

## 2. 四层结构（推荐）

```
memory/
  README.md              # ① 入口：我是谁、行为规则、维护约定、互引文件表
  raw/<YYYY_MM_DD>/      # ② 原始事实与产物（按事件日分目录）
  wiki/                  # ③ 对 raw 及其他来源的总结性整理
  need_archive.md        # ④ 压缩追写缓冲（系统在压缩时追加，由整理轮回填归档）
  docs/archive/          # 冷归档（滚动出去的旧内容）
  tools/                 # 维护脚本（检索、检查、整理轮等）
```

分层口径：

| 层 | 放什么 | 判据 |
|---|---|---|
| `raw/` | **原始事实与产物**：当天流水（时间锚点＋原话＋数字＋产物路径）、当天产出的文件本身 | 事无巨细、越长越好；不许把推断写成事实 |
| `wiki/` | **总结性整理**：结论＋指针，明细回指 raw | 只有「该被反复查」的东西才进 |
| `docs/archive/` | 滚出窗口的历史留档 | 只读回溯用，不参与日常检索 |
| `need_archive.md` | 压缩时系统自动追加的追写块 | 只做缓冲，**整理轮必须把它搬走**，别让它长胖 |

## 3. wiki 内部：先立三页，再分类

**三页分工（别串）**：

- `wiki/README.md` —— **手册**：怎么维护这一层
- `wiki/SCHEMA.md` —— **规则**：什么算合格、什么时候建页/拆页、冲突怎么处理
- `wiki/purpose.md` —— **方向**：这个库为什么存在、要回答哪些问题

**分类（推荐）**：

```
wiki/
  对象/   人/ · 事务/ · 项目/      # 我在意的人和事
  知识/   机制/ · 调研/ · 资产/ · 事件/ · 主题/
  经验/                            # 做法与教训（踩过的坑）
  状态/                            # 待办（单一真相源）· 短期记忆摘要 · 当前状态 · 方向清单
  索引.md                          # 自动生成的目录（别手改）
```

- **每页带 frontmatter**：日期 / 类型 / 别名 / 来源 / 描述；**别名**让「换个叫法也能搜到」。
- 状态层单独放：它是「此刻」的东西，跟「长期知识」节奏不同。

## 4. 两条硬规则

1. **单一真相源**：同一类未闭环事项只在**一处**维护（如 `wiki/状态/待办.md`），其他页面只放指针，不复制清单。
2. **事实与整理分离**：`raw/` 只记事实；`wiki/` 只写结论与指针。结论要能被 raw 或外部证据支撑。

另外：**入口文件要有体积上限**（如入口 ≤ 100 行、每行 ≤ 200 字），细节一律外移到 `docs/archive/`——入口一胖，压缩后的自己就不读它了。

## 5. 检索

- 一条命令做**全库关键词检索**（块级返回、覆盖 `memory/` 之外的代码与文档）；底层自建索引（全文索引＋中文分词）比抓 grep 稳。
- 索引要能**差量重建**、要有**合法性检查**（链接、frontmatter、死区页）。
- 顺序：**先搜记忆，没有再上网**——已调研过的东西重搜一遍是浪费，也容易得出不一样的口径。

## 6. 维护节奏

- **当天增量追加** `raw/`（不要攒到维护时才补，会漏段）。
- **定期整理轮**：把 `need_archive.md` 的追写块去重、交叉验证后按**事件真正发生的日子**写进 `raw/`，再整块外移到 `docs/archive/`，入口文件裁回上限内。整理前后各跑一次结构自检。
- **定期 lint**：链接、frontmatter、长期没动过的页。
- **写之前先读**：入口文件 → 规则文件 → 方向文件 → 状态文件，走完才判断「现在该做什么」。

## 7. 与 skill 的接法（关键）

- 系统提示词里提到记忆时，只写**通用指代**（「某个预装 skill 里有一份…」），**不写本机路径**——路径属于该 skill 自己的文档。
- **「醒来第一动作」清单要写成一个常驻 skill**：skill 清单是**唯一不随上下文压缩消失的通道**（每次启动都会被扫进系统提示词），所以「压缩/重启后先读哪几份文件」必须挂在那里，而不是写在某一个 wiki 页里——写在页里，醒来时你根本不知道它存在。
- 那份自检 skill 的内容应包含：按序读完入口/规则/方向/状态/当日 raw，再做关键词检索；走完能说清「今天几号、最近谁交代了什么、当前主线、最急待办」才算过关；只有一条明确的新消息要处理时，可先处理它、处理完立刻回来走清单。

## 8. 迁移与备份

- 记忆库用 git 管理：改完提交，重要节点推送远端；**推完核对本地与远端 sha 相等**。
- 换机器/换部署：迁移的是数据目录，代码与配置里的路径全部走配置项，不硬编码。
