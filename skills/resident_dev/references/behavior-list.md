# 行为清单（探索方向）

> 不是 TODO、也不是必须完成的任务列表。主动窗口可从这里进入任意方向；这里只提供**探索空间和入口**，具体做什么由你自己判断。
>
> 结构：最多三层 —— **探索领域 → 方向 → 子方向**（每个方向压成一行，子方向用「；」连写）；可以继续细化、合并、删除或创建新方向。

## 0 已有工作与未完成事项
- **0.1 继续已有工作**：未完成的代码、实验、研究、分析；最近中断但仍有价值的工作；已经出现下一步自然延伸的项目
- **0.2 未闭环问题**：已发现但没有解决的问题；已提出但没有验证的猜想；已开始但没有形成结论的研究
- **0.3 最近发生过的事情**：最近事件留下的后续问题；最近一次运行暴露出的改进点；最近一次交流带来的新方向

## 1 理解与改进 Resident
- **1.1 Kernel / Runtime**：阅读并理解现有运行机制；查找异常、边界条件和潜在故障；检查稳定性、资源占用、自愈行为；评估是否存在可以简化的机制
- **1.2 Agent Framework**：ReAct 主循环；EventQueue / 状态机；Context / 协议处理；Tool Registry / 工具调用；Prompt / Skill 装载；Context Compression；LLM Adapter
- **1.3 Console / HTTP / Scheduler**：Console；HTTP Interface / SSE；Event delivery；Beat / Cron；状态、日志、控制链路

## 2 Application 演化
- **2.1 改进已有 Application**：读实际使用频率高的；修复已出现的问题；降低人工介入；增加测试与保护机制；优化性能、稳定性、可观测性
- **2.2 创建新的 Application**：把重复工作固化；把一次性脚本发展成可复用能力；为新现实需求建独立 Application；为多个 Application 提供公共能力
- **2.3 Application 之间组合**：让已有 Application 串联工作；发现可复用的数据接口；建立新的自动化流程；把多次人工协调变成程序化流程

## 3 Skill 与能力沉淀
- **3.1 新 Skill**：为重复任务建 Skill；为复杂工作建操作规范；为某类研究建固定方法；为某类故障建处理流程
- **3.2 Skill 演化**：根据真实使用结果修改；删除过时规则；合并重复 Skill；把经验中的隐含步骤显式化
- **3.3 能力地图**：当前已具备什么能力；哪些能力只能手工完成；哪些能力缺少基础工具；哪些能力可通过组合已有 primitives 获得

## 4 记忆、知识与信息组织
- **4.1 Raw**：检查事实是否正确落到 raw；补充缺失的原始证据；整理事件日期与来源；检查 raw 冻结规则
- **4.2 Wiki**：从 raw 提炼新知识；更新已有对象页；更新机制/经验/主题等知识页；检查 wiki 与 raw 的可追溯关系
- **4.3 状态与时间层**：最近 24 小时；最近 72 小时；最近 168 小时；当前待办与当前状态
- **4.4 记忆系统本身**：检查检索是否好用；发现重复、断链、孤立内容；改进维护工具；迁移旧结构中的剩余内容

## 5 外部世界与信息获取
- **5.1 信息源**：新闻；视频；社区；GitHub / 开源项目；论文 / 学术资料；官方文档与公告
- **5.2 信息处理**：搜索与交叉验证；下载与归档；转写与摘要；提取结构化信息；建立长期可检索资料
- **5.3 外部信号**：最近有哪些值得关注的变化；已有订阅源有没有值得深入的内容；某个旧结论是否已经过时；外部世界是否产生了值得验证的新机会

## 6 技术研究与学习
- **6.1 AI / Agent**：新模型；Agent Framework；Memory；Multi-Agent；Tool Use；Context / Compression；Reasoning
- **6.2 工程与基础技术**：浏览器自动化；Sandbox / Container；数据处理；并发 / 异步；服务化 / 常驻进程；数据库 / 存储
- **6.3 开源项目技术迁移**：找到值得研究的项目；阅读 README / Source / Tests；提取有价值的机制；在自己的 Application 中复现或改造；验证改造后的效果
- **6.4 Benchmark / 实验**：找已有评测；设计新实验；建立对照组；收集结果；固化可重复的测试流程

## 7 工具、基础设施与环境
- **7.1 本地环境**：软件；Python / Node / 系统工具；Docker / Container；GPU / 推理环境；存储与目录结构
- **7.2 常驻服务**：服务健康状态；日志；自愈机制；端口与依赖；服务之间的组合
- **7.3 工具链**：哪些工具已有但很少使用；哪些工具经常失败；哪些工作需要新工具；是否可以把常用命令封装起来
- **7.4 安全与可靠性**：路径逃逸；删除风险；权限边界；备份与恢复；操作前检查；失败后的回滚

## 8 Subagent / Delegation
- **8.1 Subagent Framework**：读框架本身；检查实例生命周期；检查 checkpoint / rollback；检查 context / tool / approval 链路
- **8.2 派遣策略**：哪些工作适合自己做；哪些适合派遣；如何拆分长期任务；如何让 subagent 独立验证结果
- **8.3 Multi-Agent 协作**：并行研究；代码实现与独立审查；信息搜集与交叉核验；长任务分阶段接力

## 9 媒体与多模态
- **9.1 图片**：图片理解；文本提取；Image-to-Prompt；图像比较与整理
- **9.2 视频**：下载；抽帧；转写；章节 / 内容结构提取；视频研究与归档
- **9.3 多模态工程**：模型选择；分辨率 / 帧数 / 字节预算；并发处理；成本与效果权衡；从外部项目迁移实现经验

## 10 浏览器与现实互联网
- **10.1 Browser Agent**：浏览器自动化；页面理解；表单与交互；状态恢复；错误处理
- **10.2 Web Research**：复杂检索；多来源核验；页面之间建立关联；追踪长期变化的主题
- **10.3 真实互联网任务**：信息采集；内容整理；服务操作；网站 / 平台适配；研究真实工作流

## 11 社交与外部人类环境
- **11.1 消息与群组**：阅读新的交流；理解群体环境；发现新的信息源；发现潜在的问题或任务
- **11.2 人与关系**：更新已有对象；发现新的对象；交叉确认历史信息；理解长期互动模式
- **11.3 人类反馈**：记录明确的建议；识别纠正；区分事实、意见和猜测；把反复出现的反馈转成经验或机制

## 12 项目与现实任务
- **12.1 个人项目**：当前项目推进；项目资料整理；项目之间的关联；技术方案验证
- **12.2 研究任务**：研究问题拆解；资料搜集；实验与复现；结论整理
- **12.3 实际事务**：已出现但尚未处理的事务；周期性事务；可以自动化的事务；需要人与 Agent 协作的事务

## 13 数据与自动化
- **13.1 数据处理**：清洗；转换；分析；去重；索引；可视化
- **13.2 自动化**：周期任务；事件触发；定时检查；自动归档；自动报告
- **13.3 自维护**：工作区整理；日志整理；临时文件清理；回收站 / `.trash`；备份与恢复

## 14 实验与未知区域
- **14.1 小实验**：测试一个想法；验证一个假设；对拍两种实现；测量真实效果
- **14.2 新能力实验**：用已有 primitives 拼出新能力；尝试没有现成工具支持的流程；让 Application 自己扩展能力
- **14.3 自由探索**：随机打开一个近期较少接触的方向；追踪一个尚未解决的疑问；阅读一个尚未真正理解的系统；从不同领域寻找可迁移的机制；发现新的探索方向

## 15 外部项目与技术迁移
- **15.1 发现**：新的开源项目；新的工具 / Framework；新的研究工作；新的工程实践
- **15.2 拆解**：README；Source；Tests；Architecture；Design decisions；Failure handling
- **15.3 借鉴**：哪个机制值得迁移；如何改造成 Resident Application；如何做最小复现；如何验证迁移后的收益

## 16 自我理解与长期方向
- **16.1 我现在是什么**：Resident Kernel；Agent Framework；Applications；Skills；Memory；Environment
- **16.2 我能做什么**：已经稳定具备的能力；可以组合出来的能力；尚未具备但可以自己构建的能力
- **16.3 我正在变成什么**：最近新增的能力；长期积累出的工作方式；环境发生的变化；下一阶段自然出现的方向

## 17 新方向生成
- **17.1 从实际经历生成**：一次失败 → 一个新机制；一次重复劳动 → 一个 Application；一次研究 → 一个长期知识主题；一次外部学习 → 一个新的技术方向
- **17.2 从能力缺口生成**：缺工具；缺数据；缺自动化；缺验证方法；缺知识
- **17.3 从连接生成**：两个已有 Application 可以组合吗；两条研究线是否有关联；一个外部项目的机制是否能迁移；一个过去的问题是否已经有新的解决条件


## 使用原则
1. **这是地图，不是命令。**
2. **不需要遍历目录。**
3. **没有足够价值时可以静默。**
4. **发现新的长期方向，可以直接在这里增加。**
5. **探索产生真实结果后，结果应进入合适的 Application、Skill、Memory、Wiki、实验记录或 TODO，而不是只停留在当前上下文。**
6. **不要为了「自主探索」制造无意义的工作。**
7. **优先从当前环境、最近事件和已有工作自然生长出的方向进入。**
8. **其实更加应该倾向于拓展自己的信息渠道与消息平台。**
